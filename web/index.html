TL;DR

  • Session tokens are httpOnly cookies with a 15 minute lifetime.
  • The refresh token rotates on every use. The old one is void at once.
  • Never log a token payload. Lint catches token-shaped strings.
Contract
POST /auth/login returns 200 and two cookies. It returns 429 after 5 attempts in 60 seconds.
Invariant
A revoked session voids its refresh token in the same request. There is no grace window.

This is one page of the wiki. About 820 tokens. With JavaScript it moves through a real change: a commit lands, git dates the page past the code, ctx impact fires, the TL;DR gains the invariant, then the page is stamped.

Retrieval asks the same question twice. Compilation writes the answer down.

Every session, a coding agent re-derives the same facts about the same repository. It greps. It reads. It reasons from scratch. The work is thrown away when the session ends, and the next session pays for it again.

This system has the agent write the understanding down instead. Not into chat, and not into a folder of stale notes. Into interlinked markdown pages with front matter, a TL;DR, and a covers glob that ties each page to the code it describes.

A fresh session, a teammate, or a different tool orients from those files in two to five thousand tokens. It never re-explores. It never has to be told anything twice.

Synthesis happens once, at change time. The reading is then almost free.

Raw, wiki, schema.

Three layers, three owners, three operations. The pattern is Karpathy’s LLM wiki, applied to a repository. 

raw      immutable. the human curates
wiki     agent writes, human reviews
schema   human and agent co-evolve

  1. Raw

    the human curates

    The code itself, read only, plus context/raw/ for PRDs, meeting notes, vendor docs and exports. The agent never edits this layer. Where a source disagrees with a page, the conflict goes to the human.

  2. ↓ compiles into

  3. Wiki

    agent writes, human reviews

    Interlinked pages under context/. Every page has front matter, a TL;DR first, and a cap of 160 lines. Pages record why, contracts, invariants and gotchas. They never restate the code.

  4. ↓ ruled by

  5. Schema

    co-evolved

    AGENTS.md is read first and stays at 120 lines or fewer. Its Lessons section turns each of your corrections into one permanent line. context/index.md routes a task to the pages worth reading, and it is generated from front matter, so it cannot drift.

The three operations, plus update-on-change.
operation what runs
ingest Read the source. Summarize it. Update the affected pages, usually 3 to 15. Log it.
query Run ctx brief. Read TL;DRs. Answer with citations. File a reusable answer as a page.
lint Find contradictions, stale claims, orphans, missing links. Errors exit 1.
update-on-change Code changed, so the covering pages change in the same diff. This is what keeps month three documentation true.

The core loop.

Seven steps, every unit. Recording is not a chore at the end of a pull request. It is part of the diff, and tooling checks it.

Step 5 is the one that keeps the documentation true. The next section shows it refusing to let a session end.

  1. 01

    Orient

    Read AGENTS.md, index.md, memory.md. Skim the tracker. Run ctx brief. Do not scan the repository. Two to five thousand tokens.

  2. 02

    Plan

    Write the spec. Add the ledger entry. Ask five questions or fewer, one at a time. The human reviews for five to ten minutes and rejects weak plans.

  3. 03

    Build

    Start one unit. The command line enforces one at a time. Interface first with mock data, logic second, and the logic ships its failing test first.

  4. 04

    Record

    Write decisions, bugs and lessons as they happen. A correction that is not written down is a correction you will receive again.

  5. 05

    Context-diff

    Run ctx impact. Fix every page it marks. Cover every uncovered file. Then stamp. This is the step the next section demonstrates.

  6. 06

    Verify

    Lint, typecheck, build. Drive the real flow. Review against the spec checklist. Scale the effort to the risk.

  7. 07

    Close

    Regenerate the index. Lint. Log the build. Write memory.md with the exact next step. Then a cold agent can continue from the files alone.

The session does not end until the docs are true.

Change code. Try to stop. The Stop hook returns exit code 2 and refuses. It names the pages that describe the code you changed. Fix them, stamp them, then stop.

This is not a policy. It is a hook in .claude/settings.json. It is loop safe: it honors stop_hook_active.

One file, sixteen commands.

setup copies scripts/ctx.mjs to context/ctx.mjs. Your project carries the tool forever. Zero dependencies, so it never breaks a lockfile.

Read-only commands accept --json. Every payload carries command and ok. Continuous integration reads ok.

impact · stale · stamp · lint --fix  keep pages true to code (git-based)
index · log · new · archive          catalog, timeline, scaffolds, growth rotation
doctor · install · hook              wiring checks (12), installer, Claude hooks

Detected, not assumed.

ctx setup reads the manifests that exist. It classifies the shape: web-app, api, cli, library, mobile, data or monorepo. Then it scaffolds only what fits.

A FastAPI repository gets no Next.js flavoured pages. A docs repository gets no testing page. On existing code, setup drafts codebase/map.md from the real file census, with confidence: inferred.

Files that ctx setup writes into your repository.

context/ The wiki: router index, append-only log, architecture, standards, decisions, codebase map, module pages with covers globs, feature specs, immutable raw.

One unit. One branch. One owner.

The wiki is a committed artifact, so treat it like code. Branches own units, merges reconcile, and tooling catches collisions. Nobody negotiates in chat.

Per-unit files are the concurrency trick. Two people building two features edit two different files. Per-person files are gitignored, so nobody’s scratch leaks into anyone’s checkout.

The method in five laws.

Everything else in SKILL.md serves these five. The lint rules and the hooks exist to make them mechanical rather than a matter of goodwill.

  1. Decide what to build first.

    A line changed in a plan is free. A decision spread through the codebase is a rewrite.

  2. Make the hard calls on purpose.

    Every addition gets an explicit cost recorded in decisions.md: the options, the lost alternative, the cost paid, reversibility, and the correctness policy.

  3. Keep the state in files.

    The agent updates them while working, every session. Tooling enforces it.

  4. Never let the AI decide something important silently.

    Conflicts and gaps are flagged to the human. Every guess the text prevents is a decision that stays with you.

  5. Read cheap, then deep.

    Index line, then TL;DR, then the full page, then source code. Stop at the first level that answers.

Prompts are products.

Specs, subagent briefs, clarify questions and Lessons follow ASD-STE100, the aerospace documentation standard. It exists because ambiguity kills. In prompts, ambiguity ships bugs. This page follows it too.

ASD-STE100 rules, with a weak and a strong example each.
rule weak clear
one action per sentence The user can upload a file and it should be parsed and stored. Accept one .csv file. Parse it with the rules in data-model.md. Store rows in uploads.
name the actor The data is validated then saved. The API validates the payload. The API saves the row.
exact numbers A few retries, small file. 3 retries, 2 s apart. File size 5 MB or less.
state the result Do not make it slow or broken. The list renders in under 200 ms for 1,000 rows.
split conditions If signed in and the plan allows and the file is small, allow upload. Allow the upload only when all three are true: the user is signed in; the plan allows uploads; the file is 5 MB or less.

Give your agent the repo, not the rerun.

Setup detects your stack, scaffolds the wiki, drafts the codebase map on existing code, and self-checks with twelve doctor checks. Run it again any time. It upgrades in place.

Or paste one sentence to your agent: “Clone https://github.com/AnshRoshan/project-context-system, install it, then set up this repository.”

  1. 1

    Install the skill. It auto-detects ~/.claude and ~/.qoder.

    git clone https://github.com/AnshRoshan/project-context-system
node project-context-system/scripts/ctx.mjs install
  2. 2

    Set up any repository from its root. Any language, greenfield or not.

    cd your-project && node /path/to/scripts/ctx.mjs setup
  3. 3

    Work. Everything after this is project-relative.

    node context/ctx.mjs brief src/auth/login.ts
node context/ctx.mjs task start 03
