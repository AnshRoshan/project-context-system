# The LLM-Wiki Pattern — and how this system implements it

Source idea: Andrej Karpathy's "LLM Wiki" (gist `karpathy/442a6bf555914893e9891c11519de94f`, April 2026): instead of retrieving raw documents at question time (RAG, where the model re-derives everything each time and nothing accumulates), the LLM **incrementally builds and maintains a persistent wiki** — structured, interlinked markdown — between the human and the raw material. Knowledge is **compiled once at write time and kept current**, not re-discovered at read time. The human curates sources and asks questions; the LLM does the summarizing, cross-referencing, filing and bookkeeping that humans abandon.

For a software project the "raw sources" are the **code itself + the human's intent** (PRDs, chats, vendor docs). The wiki is the compiled, queryable understanding of both.

## Three layers

| Layer | Karpathy | This system | Who owns it |
|---|---|---|---|
| **Raw** | immutable sources | the repo's code (read-only truth) + `context/raw/` (PRDs, notes, vendor docs, exports) | human curates; never edited by the agent |
| **Wiki** | LLM-generated markdown | `context/**` pages with frontmatter: overview, architecture, codebase map, module pages, data model, API contracts, decisions, specs, tracker | agent writes and maintains; human reads, reviews, overrules |
| **Schema** | CLAUDE.md / AGENTS.md | `AGENTS.md` (+ `CLAUDE.md` wrapper) + `context/index.md` routing + `workflow-rules.md` | human and agent co-evolve it |

## Three operations

| Operation | Karpathy | Here | Trigger |
|---|---|---|---|
| **Ingest** | read source → summarize → update 10–15 pages → log | PRD/notes/vendor docs → `sources/` summary → affected pages → `ctx log ingest`. For code: *adopt/audit* a codebase into module pages | new raw material; existing project adopted |
| **Query** | search wiki, synthesize with citations, file good answers back | `ctx brief` → TL;DRs → answer → file as `type: query` page if reusable | any question or task start |
| **Lint** | find contradictions, stale claims, orphans, missing links | `ctx lint` + `ctx stale` + `ctx coverage` | session end, phase boundary, pre-commit |

Plus the one that makes software wikis different: **Update-on-change** — code changes constantly, so every code change triggers `ctx impact` and the covering pages are updated *in the same change* (the context-diff rule). This is what keeps month-three docs true.

## Two navigation files (non-negotiable)

- **`context/index.md`** — *content-oriented*. Task-routing table + a catalog of every page: link + one-line summary, grouped by type. The agent reads it first and drills down selectively. Generated by `ctx index` from frontmatter so it can't drift.
- **`context/log.md`** — *time-oriented*. Append-only, greppable: `## [2026-10-01] ingest | Stripe webhook docs`. `grep "^## \[" context/log.md | tail -10` answers "what happened recently".

## Why this beats re-exploring the repo

| Dimension | Agent explores code each session | Compiled wiki |
|---|---|---|
| When synthesis happens | every task, from scratch | once, at change time |
| Cost per session | 20–100k tokens of reading | 2–8k tokens of orientation + targeted pages |
| Knowledge of *why* | absent (code shows what, not why) | decisions, invariants, gotchas recorded |
| Consistency across agents/tools | each agent builds its own mental model | one shared model |
| Contradictions | invisible | flagged by lint, resolved by the human |

## Where the pattern breaks — and the guards built in

| Failure mode | Guard |
|---|---|
| Wiki outgrows the context window (~150–200 pages) | index one-liners; `brief` ranks + budgets; sub-indexes at scale (see `context-routing.md`) |
| Pages rot as code moves | `covers:` globs + git-based `ctx stale`/`impact` + Stop hook |
| Agent writes unverified guesses as facts | `confidence: verified | inferred | unverified`; unverified is shown in the index and never trusted blindly |
| Agents ignore formatting rules | enforced by `ctx lint`, not by prose; required frontmatter fields |
| Duplicate pages, orphaned pages | `ctx lint` orphan check, `ctx index` catalog, search-before-create rule |
| Copy of code in prose goes stale instantly | rule: link by path + symbol; document contracts and why, not bodies |
| Wiki and human intent diverge | raw layer is immutable; conflicts go to the human, never silently overwritten |
| Context bloat from "just in case" pages | page-worthiness test; archive instead of delete |

## llms.txt

`llms.txt` (llmstxt.org) is the web convention for exposing a curated markdown index to LLMs. Here `ctx index --llms` emits one at the repo root from the same frontmatter — useful for tools/agents that look for it, and for exposing project docs publicly. It is a derived artifact; `context/index.md` stays the source of routing.
